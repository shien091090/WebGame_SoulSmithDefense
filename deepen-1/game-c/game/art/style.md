# 魂匠共鳴 美術規格(deepen-1 / game-c)

> RD 只讀這份。`index.html` 必須宣告 `<meta charset="utf-8">`, 否則 art.js 的中文字會變亂碼。
> art.js 是一般 script(不是 module), 載入後提供 `window.Art`。全部 Canvas 2D 幾何繪製, 沒有外部資源; 字型只用系統字型(微軟正黑體 → 蘋方 → sans-serif)。

## 邏輯畫布尺寸

`window.Art.canvas = { width: 1280, height: 720 }`(= interface.json)。HUD 0~50, 遊戲區 y 50~720。

## 形狀語言

我方 = 帶藍邊的方正幾何(圓角方塊); 敵人 = 下緣波浪的「鬼」剪影 + 橘眼; 玩家 = 全場唯一的奶白金邊圓; 基本魂件 = 圓角方塊 + 深色線圖示, 組合魂件 = 金邊八角 + 斜分雙色(兩件原料的色)+ 組合圖示; 借來的(虛)魂件 = 小一號、虛線框、半透明; 扁平無漸層, 只有爐火與範圍淡染用漸層。

## 理念落實

- P0 辨識度先於好看: 我方 / 敵 / 玩家 / 中立 四類用剪影分(方塊 / 鬼 / 圓 / 灰無邊方塊), 不靠顏色; 魂件以圖示形狀為主通道。
- P1 視覺權重跟著決策迫切度走: 地面層(魂柱範圍、主堡區、冰霜範圍)全部 ≤ 12% 不透明淡染; 最亮的是互動目標白框、彈窗游標金框與出怪預警, 組合名稱與特效都比它們弱。
- P2 規則上存在的東西畫面上就存在: 共鳴線、借來的虛魂件格、屍體剩餘時間細條、倒下圓餅、敵人失去進攻主堡時的問號都畫出; 魂柱範圍外緣 = 150 判定邊界, 冰霜範圍外緣 = 70。
- P3 一個意義一種長相: 魂件圖示在槽列、地上、手上、彈窗、商店、HUD 魂爐用同一個函式畫; 意象色在魂柱晶石、範圍圈、共鳴線、虛魂件格一致; 說明頁直接呼叫遊戲內函式。
- P4 關鍵區分走兩條通道: 實體 vs 借來 = 大小(18 vs 14)+ 實線底 vs 虛線半透明; 我方 vs 敵方攻擊 = 箭形 vs 圓彈 + 黃白 vs 紅; 我方 vs 敵方冰霜範圍 = 實線冰藍 vs 虛線粉紅; 共鳴線 vs 搶奪連線 = 直線意象色 vs 金色鋸齒鏈; 基本 vs 組合魂件 = 方 vs 金邊八角 + 單色 vs 雙色。
- P7 每個元素都要掙得版面: 魂件格不加文字名稱(圖示已說明); 說明頁示意圖不重寫彈窗自帶的按鍵字(見說明頁一節)。
- P9 以最混亂的那一刻驗收: 互動目標框用純白粗 3 線 + 呼吸, 在滿場鬼與範圍圈重疊時仍是唯一的白框; 文字一律帶深色底板或描邊。
- P13 事件要排隊: 組合名稱在 1.5 秒內先彈後飄、最後 40% 淡出, 同一個單位的連發由 RD 照規格 4 秒去重; 美術不讓名稱留到下一個出現。
- P15 回饋強度與份量成正比: 單體命中 = 小火花(半徑 12)< 範圍斬擊(60)< 穿透光束(整條線); 一般組合名 = 小白字暗底, 首次組合 = 大金字金邊「新組合!」。
- P17 進度圖形與數字分工: 出怪預警中央數字是剩餘秒數(無條件進位), 外環只畫「這一秒還剩多少」; 搶奪環、倒下圓餅、屍體細條沒有數字, 照舊畫總進度。
- P18 重要資訊不只存在一瞬間: 首次組合的名稱只閃 1.5 秒, 但 HUD 魂爐 5 格會常駐點亮該組合的圖示。
- P19 資訊貼著物件: 魂件槽列貼在單位頭上, 搶奪進度是繞玩家的環, 倒下倒數畫在單位本體內, 主堡區的「空白鍵」小鍵帽貼在主堡區圈上。
- P21 示意圖選分岔的例子: 第 6 頁同時放圈內兩座冰箭弩塔與圈外一座普通箭弩塔(「圈內才有」); 第 7 頁並排「路旁可放」與「路上不可放」。

## 繪製層級(照 interface.json drawOrder)

drawBackground → drawPillarRange → drawResonanceLine → drawFrostAura → drawCoin → drawCorpse → drawGroundPart → drawPlacePreview → 單位(依 y)→ drawSoulSlots → drawProjectile → drawPierceBeam → drawAreaHit → drawHitSpark → drawStealLink → drawComboName → drawSpawnWarning → drawHud → drawSlowMo → drawSoulPopup / drawShopPopup → drawResult。說明頁: drawGuidePage。

## 判讀約定

- 時間欄位: 0 ≤ Age < Duration 才播; Age ≥ Duration 或欄位缺漏 = 閒置。缺 Duration 時用介面的預設(攻擊 0.15、受擊 0.2、主堡受擊 0.3、魂柱波紋 0.5、魂爐彈出 0.6、穿透 0.15、範圍 0.3、火花 0.25、組合名 1.5、抖動 0.25、倒下 5)。
- 半徑一律指外緣: 魂柱範圍 150、冰霜範圍 70、主堡區 110、旋風斬 / 冰霜重擊 60、衝鋒 30、搶奪環 24(環寬 4, 範圍 20~24)。有寬度的線(範圍圈線寬 2.5、主堡區虛線)往內畫, 不超出外緣。
- 穿透光束: 最寬層 28(中線兩側各 14)= 判定寬。
- 出怪預警數字 = ceil(remaining); 外環 = remaining − (數字 − 1), 每秒重跑。
- 表外值的預設外觀: 敵人 / 屍體種類未知 → 小鬼; drawAreaHit kind 未知 → 旋風斬; drawPlacePreview kind 未知 → 弩塔; 物品字串未知 → 只畫一個虛線空框(不冒充任何魂件); 商店品項缺漏 → 鎖住格。看到這些預設外觀時請查傳入值。
- 說明頁 page 超出 0~7 會夾到最近的一頁。
- 時間性的小動畫(呼吸、流動光點、雪點繞行、爐火)用 `performance.now()` 自己跑, 不影響狀態。

## 畫面文字歸屬

除了說明頁, 畫面上所有文字都由美術畫(依介面 textOwnership): drawComboName、drawSoulPopup(標題、「手上」、「丟下」、動作提示、「Z 確定  X 關閉」)、drawShopPopup(「商店」、品名、價格、底部訊息、「← → 選  Z 購買  X 關閉」)、drawHud(金幣、主堡 n / 20、波次 n / 6、下一波 N 秒、「魂爐」、「每波開始送出」、右側「Z 互動  X 自己  空白鍵 商店」)、drawSlowMo(「慢動作」)、drawResult(標題、波次、組合數、「按 Z 重新開始」)、drawCastle(主堡區內的「空白鍵」小鍵帽)。**RD 不要另畫這些字。**

說明頁: 介面的文字歸屬寫「除了說明頁」, 且 state 只有圖框 → 依任務分工, **美術只畫示意圖**(含物件旁的短標籤), 頁標題、說明文字、頁碼、翻頁提示由 RD 畫, 而且要畫在示意圖框 (x, y, w, h) 外面。
