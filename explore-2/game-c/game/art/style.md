# 魂匠收編 美術規格(explore-2 / game-c)

RD 只讀這份。`index.html` 必須宣告 `<meta charset="utf-8">`(art.js 內有中文字串)。所有函式都是 `window.Art.drawXxx(ctx, state)`, 每個函式自己 save/restore; 函式名、state 欄位一律照 interface.json。

## 邏輯畫布尺寸

`window.Art.canvas = { width: 1280, height: 720 }`。上方 y 0~50 為 HUD。

## 形狀語言

扁平幾何、深色描邊、圓角方格裝魂件; 三陣營同一造型只換「本體色 + 眼睛 + 外框線型」: 敵方紅身黃色怒眼, 我方藍身白眼加白頭帶(野狼為白項圈), 中立灰身空洞黑眼加虛線外框、半透明。

## 理念落實

- P0 辨識度先於好看: 每種魂件同時有專屬形狀(箭 / 劍 / 盾 / 眼 / 城堡 / 六角十字)與專屬色, 全畫面同一套圖示。
- P1 視覺權重跟著決策迫切度走: 只有「互動目標」用純白粗外框, 全畫面沒有其他白框; 背景草地與路面低飽和、不動。
- P2 規則上存在的東西畫面上必須存在: 敵人沒有攻擊魂件(harmless)就拿掉武器、眼睛變扁、身體洩氣; 被拆掉進攻主堡停下來時腳不動; 屍體剩餘時間畫成底部細條, 最後 3 秒閃爍; 主堡區用地面圈畫出。
- P3 一個意義一種長相: 魂件圖示在槽列、地上、玩家頭上、彈窗、商店都由同一個圖示函式畫; 我方藍 = 箭塔 / 步兵 / 收編兵 / 主堡 / 可放置提示; 綠 = 鐵壁, 吸引範圍也用綠。
- P4 關鍵區分走兩條通道: 敵 / 我 / 中立 = 顏色 + 眼睛造型 + 外框線型(中立虛線)+ 面向(敵人朝右、收編兵朝左); 屍體與迷魂 = 倒地旋轉 + X 眼 vs 站立 + 空洞眼; 空格與有魂件格 = 虛線無底 vs 實底彩框。
- P7 每個元素都要掙得它的版面: 血條只在受傷時畫; 中立單位不畫血條; 重生列不寫秒數(計時圈已表示); 屍體不寫秒數。
- P9 以最混亂的那一刻驗收: 所有文字帶黑描邊; 互動目標框帶白光, 滿場時仍撿得到。
- P13 事件要排隊: 技能名稱 1.5 秒內先彈後飄, 最後 0.5 秒淡出, 只佔單位頭上槽列之上那一帶, 不和槽列重疊。
- P15 回饋強度和事件份量成正比: 單體命中 = 24px 小火花; 範圍技 = 填滿判定圈的特效; 本局首次技能 = 金框加大字「新技能!」, 一般技能名 = 灰白小牌。
- P17 圖形與數字分工: 出怪預警中央數字給剩幾秒, 外環只畫「這一秒還剩多少」; 地基重建圈畫總進度並配秒數(數字顯示剩餘秒、圈給填滿程度, 地基上沒有別的地方能放)。
- P18 重要資訊不能只存在一瞬間: 收編結果常駐在 HUD「收編 N / 5」與商店剪影解鎖成品項, 不只靠一次性演出。
- P19 資訊貼著物件: 手上物品畫在玩家頭頂; 搶奪進度是繞玩家的圓環; 搶奪連線直接連到被搶那一格。
- P21 示意圖選對錯理解會分岔的例子: 說明第 6 頁第 1 格畫「剩最後一件 [近戰, 空] 的敵方小鬼」, 不是空殼小鬼; 第 4 頁畫虛線圈標出斷線距離。

### 畫面文字歸屬

除說明頁外, 以下文字全部由美術畫, RD 不要另畫: 技能名稱、彈窗(標題、「手上」、動作提示、「J 確定  K 關閉」)、商店(鍵帽、品名、價格)、HUD 全部數值與「第 / 波」「下一波」「收編」、重生列「+N」、出怪預警秒數、地基重建秒數、「慢動作」、結算畫面全部字(含「按 J 重新開始」)。
