**色票張力**: 魂件七色以「圖示形狀」為主通道(箭 / 劍 / 眼 / >> / 盾 / 雪花 / 石塊+), 顏色第二。近戰紅(5°)與進攻主堡黃(46°)色相相鄰、鐵壁藍與冰霜淡藍相差約 30°, 但這兩對的形狀與明度都差很多(劍 vs >>; 中明度盾 vs 極淡雪花)。進攻主堡黃與金幣色名接近, 但金幣只在地上、魂件只在深色格裡, 類別不同不同框。最差一幀: 盾鬼屍體槽列 [鐵壁, 近戰, 進攻主堡] 旁邊有冰霜圈。

## 形狀語言

扁平、圓角、無黑外框; **我方 = 方正藍石(雉堞、頭盔)、敵人 = 紅色圓身 + 尖角 + 黃色斜眼、玩家 = 紫色圓身 + 白外圈、中立 = 灰**; 尖角只長在敵人身上。

## 理念落實

- **P0 辨識度先於好看**: 陣營靠「顏色 + 剪影」雙通道(藍方塊 / 紅圓角鬼 / 紫圓白圈); 魂件以圖示形狀分, 不靠顏色。
- **P1 視覺權重跟著決策迫切度走**: 最亮的元素只給「現在要按 J 的東西」(黃色互動外框、彈窗游標); 背景與路低對比; 冰霜圈只鋪 12% 淡色。
- **P2 規則上存在的東西畫面上就存在**: 倒下單位有計時圈(會回來)、空格畫虛線框(還能裝)、擴槽石格底與魂件不同(不參與組合)、屍體 / 魂件堆最後 3 秒閃爍、主堡區畫成地面圈。
- **P3 一個意義一種長相**: 黃框 = 互動目標(主堡、單位、敵人、屍體、魂件堆都一樣); 魂件圖示在槽列、彈窗、說明頁同一套; 我方特效一律天藍、敵方一律紅; 說明頁直接呼叫遊戲內畫法。
- **P4 關鍵區分走兩條通道**: 我方 vs 敵方特效 = 顏色 + 線型(冰霜圈外緣實線 / 虛線; 投射物同形但敵人用紅); 冰箭 vs 普通 = 菱形冰晶 vs 尖鏢; 空格 vs 有魂件 = 虛線無底 vs 實心深底 + 色框。
- **P7 每個元素都要掙得版面**: 屍體 / 魂件堆不畫剩餘時間條, 只在最後 3 秒閃; 說明頁不另畫「J 拿」「K 關閉」(彈窗本身已寫「J 確定 K 關閉」)。
- **P9 以最混亂的那一刻驗收**: 互動外框用 3px 亮黃、彈窗游標 3px 黃框 + 指示三角, 滿場時仍撿得到; 慢動作同時用去色 + 冷色 + 暗角 + 邊框 + 字五條。
- **P13 事件要排隊**: 組合名稱只出現在單位頭上、退場前淡出, 不在畫面中央疊字。
- **P15 回饋強度和事件份量成正比**: 一般組合 = 深底黃字小牌; 本局首次 = 實心金底大牌 + 白框; 命中火花只有 24px。
- **P17 進度圖形與數字分工**: 出怪預警數字給剩幾秒、底板在最後 2 秒加快閃爍; 倒下計時圈與搶奪環沒有數字, 圖形畫總進度。
- **P18 重要資訊不能只存在一瞬間**: 組合名稱閃過後, 組合本身仍可從槽列的兩件魂件讀出。
- **P19 資訊貼著物件**: 魂件槽列、血條、組合名稱、搶奪環、箭塔材料圖示都貼在該單位旁; 說明頁的鍵帽貼在做動作的物件旁。
- **P21 示意圖選分岔的例子**: 第 5 頁畫出保持距離的虛線圈(玩家在圈內), 分開「貼著才能搶」與「離太遠就斷」。

## 判讀約定

- 所有 `xxxAge / xxxDuration`: 照介面, 0 ≤ Age < Duration 才播; 其餘(含 Age = Duration 的閒置值)不畫該動作。
- `drawFrostAura.radius` = 冰霜判定外緣(70); 填色到 radius、外緣線畫在 radius 內側 1px。
- `drawWhirl.radius` = 斬擊外緣(60), 斬弧畫在 radius 內。
- `drawPierceBeam`: 外暈寬 26(判定 28 內), 越接近 duration 越淡。
- 玩家搶奪環: 半徑 22 為環中線、寬 4 → 外緣 24, 從正上方順時針填。
- 屍體 / 魂件堆閃爍: `life < 3` 時以 0.2 秒為一拍在不透明 1 / 0.3 之間切換(不會淡到看不見)。
- 表外值的預設畫法: 未知 `type` / `kind` → 小鬼; 未知 `team`(投射物、光束、旋風、冰霜圈)→ 我方; 未知魂件字串 → 格內一個灰點(不畫成任何魂件); 商店 `state` 未知 → 當成 poor(變暗)。看到不該出現的灰點或小鬼, 請查傳入值。
- 刻意不讀的欄位: `drawCorpse.maxLife`、`drawSoulPile.maxLife`(閃爍只看 life < 3)、`drawPlayer.invulnTotal`(無敵只閃爍, 不畫進度)、`drawSpawnWarning.total`(只顯示剩餘秒數)。
- `drawShopPanel` 固定畫在中心 (640, 672); 另接受可選的 `x, y`(說明頁用), 遊戲內不必傳。
- 時間性動畫(走路晃動、預警閃爍、無敵閃爍、搶奪連線流動)用 `performance.now()` 自己算, 不需要 RD 傳時間。

## 畫面文字歸屬

美術已畫(RD 不要再畫): 組合名稱、彈窗標題 / 「目標」「身上」排標 / 動作提示 / 「J 確定  K 關閉」、商店按鍵 / 品名 / 價格、HUD 所有數值與「第 N / 6 波」「下一波 N 秒」、「慢動作」、結算標題 / 波次 / 「按 J 重新開始」、出怪預警的倒數數字。

## 繪製層級

照介面 `conventions.drawOrder`。主堡區圈畫在 `drawCastle` 內、主堡本體之下; 因單位依 y 排序, 主堡區圈可能蓋在 y 較小的單位之上(只有 16% 淡色, 不影響辨識)。若要完全在單位之下, RD 可把 `drawCastle` 固定排在單位群最前面。
