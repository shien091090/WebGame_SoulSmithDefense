色相與灰階(node 算): 遠攻 31° / 灰 ~171、近戰 317° / 156、索敵 118° / 170、進攻主堡 186° / 172; 四色兩兩色相差 ≥ 68°。魂件四色灰階接近, 第二通道是**符號**(箭 / 劍 / 眼 / 城), 不是明度。
我方藍 216°、敵紅 0~3°(弓鬼 343°)、玩家紫 260°、金幣 46°。

**張力(請用這一幀驗收)**: 遠攻橘(31°)與金幣金(46°)只差 15°。兩者靠類別層分開: 金幣 = 小(16)、無符號、內圈一道環、無影; 遠攻魂件 = 大(地上 28)、深色箭符號、粗深外框、腳下有影。最差組合是「地上掉著遠攻魂件, 旁邊一圈剛噴出的金幣」。

## 形狀語言

扁平填色 + 2px 深色外框; **我方 = 圓角方塊、無尖角**(藍), **敵人 = 尖角(角、背刺、尖帽兜)**(紅), 中立 = 灰色閉眼; 魂件 = 彩色圓 + 深色符號, 其他物品 = 羊皮紙方牌; 白色只代表「玩家此刻的互動焦點」。

## 理念落實

- P0 辨識度先於好看: 敵我分兩條通道(紅 + 尖角 / 藍 + 圓角), 中立再多一條(灰 + 閉眼); 背景只用低對比草地斑塊, 不放裝飾物。
- P1 視覺權重跟著決策迫切度走: 全畫面最亮的白色只給「互動目標外框 / 選中格 / 按住進度環 / 可蓋地基」, 也就是玩家此刻按 J 會作用在哪; 預警用全畫面唯一的橘紅閃爍; 背景與路線壓低對比。
- P2 規則上存在的東西畫面上就存在: 空槽位也畫(虛線空格), 槽位上限一眼數得出; 屍體保留剩餘時間(越淡越快消失); 中立單位「不屬於任何一方」畫成閉眼灰石; 主堡區畫成地面圈, 進入時變實線。
- P3 一個意義一種長相: 四種魂件的圖示在槽列、玩家手上、地上物品、說明頁全部是同一個繪製函式; 商店、手上、地上的箭塔材料 / 步兵 / 石魔像都畫成縮小的遊戲內單位; 白框 = 互動目標, 不另作他用。
- P4 關鍵區分至少兩條通道: 敵 / 我(色相 + 尖角 vs 圓角)、中立 / 我方石魔像(灰 vs 藍灰 + 閉眼 vs 發光眼 + 有無胸帶)、我方 / 敵方投射物(淡藍 vs 紅 + 箭形 vs 圓彈)、魂件 / 非魂件物品(彩色圓 vs 方牌)、空格 / 有魂件(虛線空框 vs 實心彩色圓)。
- P7 每個元素都要掙得版面: 單位不畫名字, 血條只在受傷時出現; 商店面板沒有標題字; 說明頁只在物件旁放兩個字的標籤與鍵帽。
- P9 以最混亂的那一刻驗收: 選中格是 2.5px 白框 + 外側黑線, 壓在任何單位、路面上都讀得到; 預警帶深色外框; 魂件圖示有深色外框, 疊在紅敵人頭上也分得開。
- P13 事件要排隊: 本作沒有文字類事件提示(預警是固定位置的常駐倒數, 結算是全畫面), 無需排隊; 預警最多三個, 位置互不重疊。
- P15 回饋強度和份量成正比: 單位受擊只閃白 0.2 秒(小)、命中火花 24px(小)、主堡被突破整座閃紅 0.3 秒(大)、預警帶閃爍與倒數(最大、決策用)。
- P17 進度圖形與數字分工: 預警的數字給剩幾秒, 外圈白環只畫「這一秒還剩多少」; 按住 J 的進度環沒有數字, 照舊畫總進度; HUD 主堡生命數字 + 條。
- P18 重要資訊不能只存在一瞬間: 主堡被突破的閃紅之後, HUD 生命數字留住結果; 波次與下一波倒數常駐 HUD。
- P19 資訊貼著物件: 魂件槽列在單位頭上、手上物品在玩家頭上、按住進度環繞著玩家、血條在單位頭上。
- P21 示意圖選對錯理解會分岔的例子: 說明第 3 頁同一座箭塔並排「拆之前 [遠攻, 空] / 拆之後 [空, 空] + 手上拿著」, 讓玩家看出「拆下 = 原單位失去它」而不是複製; 第 5 頁步兵按 J 直接出現在腳下, 對比箭塔材料必須按住 J 蓋在地基上。

**物品圖示(itemKinds)**: ranged / melee / seek / march = 彩色圓 + 深色符號(斜箭 / 直劍 / 眼睛 / 小城); slotStone = 方牌上的淺藍六角晶石 + 「+」; towerKit / soldierKit / golemKit = 方牌上縮小的箭塔 / 步兵 / 我方石魔像。

**畫面文字歸屬**: 單位、HUD、商店、結算的所有字由美術畫, RD 不要再畫。說明頁例外(見下)。

**表外值的預設外觀**(RD 看到這些外觀表示傳錯值): enemy type 不明 → 小鬼; corpse kind 不明 → 小鬼屍體; golem team 不是 "ally" → 中立; lane 不明 → 西; item 不明 → 不畫; shop state 不明 → ok; 缺的 shop 項 → 鎖住。

## 繪製層級

照 interface.json 的 drawOrder: 背景 → 地基 → 金幣 → 地上物品 → 屍體 → 單位(依 y)→ 魂件槽列 → 投射物 → 火花 → 預警 → 玩家 → 商店 → HUD → 結算。主堡區圈畫在主堡函式裡, 因為主堡依 y 排序, 圈只用細線(平常虛線、進入時實線 + 8% 淡色), 壓到 y 較小的單位時不遮住它們。

## 說明頁

**分工**: `drawGuidePage` 只在 `(x, y, w, h)` 框內畫示意圖, 頁標題、說明文字、頁碼、翻頁提示由 RD 畫。圖裡只有物件旁的兩字標籤(「主堡」「預警」「按住」「換格」「屍體」「中立」)、鍵帽、「+2」。
**偏離說明**: 介面的文字歸屬寫「畫面上所有文字都由美術畫」, 但介面沒有列 `drawGuidePage`, state 也不傳頁面文字; 本作照任務單的說明頁分工。**RD 請在框外自己畫說明頁的標題與文字**。
