# 美術經驗提案(魂匠守衛者 打磨第 13 輪)

## 提案 1 — 放進「經驗 / 視覺層級」, 掛 P10(可並列到「換皮把背景調亮」之後)

- HUD 裡的小圖示被規格搬到遊玩區(魂匠守衛者 打磨第 13 輪: 聲音開關從頂端資訊列移到資訊列下方、遊玩區右上角), 沿用原本在 HUD 裡的淡底板(35% 黑)會壓在草地、路面、範圍淡染上, 喇叭的白線失去固定的深底(建置設計判斷, 非老闆回饋, 不算升格證據) → 圖示在 HUD 時靠的是 HUD 的純深色底撐對比, 搬家時只改了座標、沒重驗背景 → 從固定深底區搬到遊戲世界上的 UI 元件, 底板改成 HUD 本身的深色(約 85% 不透明)+ 1px 淡亮邊, 自己帶著 HUD 的底走, 看起來也像 HUD 往下延伸的一角〔P10〕〔P11〕

## 提案 2 — 放進「經驗 / 與規格的分界」

- interface.json 的 canvas 有 maxWidth(發布用的加寬上限), 任務範本要「照 screen-width 保留依裝置決定寬度的做法」, 但規格與 interface notes 明寫「本輪不加寬, art.js 匯出 Art.canvas.width = 1280, game.js 從它讀」, 而且上一版 art.js 本來就沒有選寬度的程式(魂匠守衛者 打磨第 13 輪, 建置設計判斷) → maxWidth 只表示「接合檢查接受的上限」, 不等於這一輪要開加寬; 美術若自己加上依裝置選寬度, 觸控裝置會拿到 > 1280 的畫布, 而 RD 這輪沒做 `OX` 平移, 畫面會整個偏左 → 「保留」指上一版已經有才保留; 上一版沒有、規格又明寫不加寬時, 匯出固定 width(= interface 的 width), 但全畫面層照規範畫滿 −(1680−1280)/2 起的寬度, 等發布輪一起開; 判斷寫進 style.md 與回報
